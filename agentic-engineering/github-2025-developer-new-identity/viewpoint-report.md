# 開発者の新たなアイデンティティ：AI時代に何が変わり、何が変わらないのか

## 🎬 結論：このコンテンツの使い道

- **動画として使うなら**:
  - ◎ 推奨: 「エンジニアの未来」「AI時代の役割転換」をテーマにした **解説／対談動画の主ソース**。視聴者の "自分ごと化" を促す導入として極めて優秀（"もし私がコードを書いていないとしたら…" の問いかけが強力）
  - ✗ 避ける: 「CLAUDE.md でハーネスを組む」「フックでコミット前検査を自動化」「MCP で外部 API を叩く」など **実装 HowTo 動画の主ソースには不向き**（具体例ゼロ）
  - フック候補: 「**コード作成者から、コードのクリエイティブディレクターへ**」／「**生成作業よりも検証作業に多くの時間を費やしている**」／「**TypeScript が GitHub 月間貢献者数 1 位**」

- **記事化（Zenn / note / Tech Blog）するなら**:
  - ◎ 推奨: ビジョン記事／キャリア論／「3年後のエンジニア像」系の **オピニオン寄せ記事**の根拠引用に最適。GitHub の Octoverse データ（80%・100万PR・TypeScript 1位）が論拠として強い
  - ✗ 避ける: 実装 Tips・ツールチュートリアル・YAML 設定例が必要な記事の主ソース

- **補強が必要なテーマ**:
  - **ハーネス整備（CLAUDE.md・ルールファイル・フック）** → ハーネスエンジニアリング系の別記事で補完
  - **レビュー疲労・小さな PR・トリアージ運用** → DORA レポート、GitClear 等で補完
  - **観測・計測（コスト／トークン／成功率）** → 別ソース必須
