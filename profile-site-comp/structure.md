# Miyabiya Studio サイトカンプ 構成の意味付け

見る人は5種類。各セクションは「誰に / 何のために / なぜこの位置 / 何を載せるか / CTA」で意味付けし、答えられない要素は置かない。

- 採用担当 (転職活動中の場合)
- 開発・AI導入・PRを頼みたい企業
- コラボ・タイアップを考える企業・個人
- メンバーシップを検討中で、運営者を慎重に確かめたい人
- 登壇を依頼したいイベント運営

## 1. ヒーロー (`#hero`)

- **誰に**: 全員 (最初の5秒)
- **何のために**: 「本業でAI駆動開発を回している実務者で、YouTubeも本気で運営している人」だと分からせる
- **なぜこの位置**: 5人とも最初に確かめるのは「この人は誰で、信じてよいか」。だから先頭に置く
- **何を載せるか**: キッカー=肩書き。H1=ブランドの一言。その直下に証拠3項目 (テックリード / 開発工数を50〜75%削減 / YouTube登録者3,350人) を1行で置き、流し読みでも根拠が目に入るようにする。リード=本業と個人の要約+受けている相談の4種。写真=本人。数字は公開時に取り直す。プロフィールセクションは削除 (2026-09-04)。本人の写真はここ、YouTube / X / GitHub のリンクはヘッダーとフッターに置く
- **CTA**: 主=XのDM (依頼する人)、副=YouTube (話し方や発信を確かめたい人)。2つのボタンは同じ幅

## 2. ご用件から選ぶ (`#route`)

- **誰に**: 全員
- **何のために**: 自分の用件のセクションへ最短で着く。全部読ませない
- **なぜこの位置**: 「誰か」が分かって読む気になった直後に振り分ける。この下は用件ごとの着地点になる (数字で見るは2026-09-04に削除。登録者などの数字はヒーローと実績に入っている)
- **何を載せるか**: 5つの用件 = 5人の訪問者に1対1で対応。文言は訪問者の言葉で「〜したい」「〜している」に揃える。こちらの分類名は出さない。同じ幅の枠で並べる
- **CTA**: 各セクションへの内部リンク

## 3. 事業内容 (`#services`)

- **誰に**: 依頼企業 (開発・AI導入・PR)、コラボ相手、登壇運営
- **何のために**: 何を頼めて、何が得られるかを「依頼の形」で示す
- **なぜこの位置**: 信頼が取れた次に来る問いは「では何を頼めるか」。数字の直後に置く
- **何を載せるか**: つくる・組み込む3枠 (開発 / ハーネス設計の相談 / 導入支援) と発信2枠 (PR・コラボ / 登壇)。各枠は対象と得られる結果を1〜2文、末尾に依頼の形のチップ。PR枠には視聴者層と個人コラボの入口。料金表はPRだけ折りたたみで置き、常時は見せない。冒頭に「お見積もりは無料」
- **CTA**: PR枠→料金表、登壇枠→登壇セクション。依頼そのものはページ末尾のDMへ

## 4. 実績 (`#works`)

- **誰に**: 依頼企業・採用担当 (本業のカード)、コラボ相手・メンバーシップ検討者 (YouTubeのカード)
- **何のために**: 「できること」の裏付けを、やったこと→結果の形で示す
- **なぜこの位置**: 依頼内容を読んだ直後に「本当にできるのか」に答える
- **何を載せるか**: 本業2件 + 個人1件の3枚 (2026-09-04 ユーザー指定の内容)。AI駆動開発環境の構築・運用 (工数50〜75%削減 / デモ準備4時間→20分) → MCPサーバー開発とプロジェクト推進 (社外クライアント・社内運用チームの工数削減 / エージェントスキル配布でノウハウ共有と底上げ) → YouTube運営 (登録者3,350人・メンバー30人以上、制作・公開フローをAIで仕組み化)。見出しは結果を先に。社名は伏せ、数字は公開前に掲載可否を確認。末尾に「お問い合わせ」ボタンを1つ (証拠を読み終えた直後の出口)
- **CTA**: なし

## 5. 代表的な動画 (`#videos`)

- **誰に**: PR・コラボ相手、メンバーシップ検討者、登壇運営
- **何のために**: 話し方と内容の質を、リンク先へ行かずにこのページで確かめてもらう
- **なぜこの位置**: 実績の直後。数字の裏にある実物を見せる位置。3者とも「実物を見てから動く」
- **何を載せるか**: Claude Codeを中心に、チャンネルの方向性が分かる本編3本 (サムネイル・タイトル・再生数・公開月)。再生数順ではなく、いまの発信内容を代表する3本を選ぶ (再生数上位は2023年のVSCode動画で、いまの方向性と違う)。数字は公開時に取り直す。末尾に「メンバーシップをご検討の方へ」の枠 (動画を見た直後に加入を検討する導線。プロフィール削除に伴い移動、2026-09-04)
- **CTA**: 各カードがYouTubeへのリンク

## 6. 技術登壇実績 (`#talks`)

- **誰に**: イベント運営
- **何のために**: 依頼前に知りたいこと (実績・テーマ・形式・話し方・告知用の素材) を一か所に揃える
- **なぜこの位置**: 実績の直後。登壇も実績の一種なので続けて読める。運営は振り分けからここへ直接来る
- **何を載せるか**: 実績2件はイベントページへ実リンク。「お話しできるテーマ」「対応できる形式」を枠で。Japan IT Week (出展) は載せない (2026-09-04 決定)。未確定のものは載せない
- **CTA**: 「登壇を依頼する」(DM) と「動画で話し方を見る」(YouTube)。同じ幅

## 7. 経歴 (`#career-history`)

- **誰に**: 採用担当、開発を頼みたい企業
- **何のために**: どんな土台の上でAI・MCPを使っているかを、経歴の流れで示す
- **なぜこの位置**: 実績と登壇 (何ができるか) を見たあとに、その根っこ (どう育ってきたか) を確かめる順。採用担当はここからプロフィールと採用枠へ進む
- **何を載せるか**: SIer → Web系 → Web系 (現職) の3段の時系列。フロントエンド・バックエンド・インフラの幅、自動テストとクリーンアーキテクチャによる保守性の高い開発、その土台の上でのAI・MCPによる成果創出。年と社名は出していない (入れるなら値をもらう)。末尾に「採用ご担当の方へ」の枠 (経歴を読んだ直後に採用相談へ。プロフィール削除に伴い移動、2026-09-04)
- **CTA**: なし

## 8. ご依頼の流れ (`#flow`)

- **誰に**: 依頼企業・登壇運営・採用担当
- **何のために**: 連絡したら何が起きるかを見せ、DMを送るハードルを下げる
- **なぜこの位置**: 最後のCTAの直前。「送ったらどうなるか」の不安を消してから出口へ
- **何を載せるか**: 4ステップ (相談→ヒアリング→提案と見積もり→着手)。見積もりは無料、合わなければ終了してよい、を明記。登壇・PRはヒアリングを省く旨。返信の目安・稼働の目安は載せない (2026-09-04 決定)。ヒアリングが無料かどうかも書かない (同日決定)
- **CTA**: なし (直下の問い合わせ帯へ)

## 9. お問い合わせ (`#contact`)

- **誰に**: 全員
- **何のために**: 行動させる。ページ唯一の出口
- **なぜこの位置**: 末尾。どの用件で来ても最後はここに着く
- **何を載せるか**: 青い面はこの帯だけ (DSの規則)。「用件を一言」で敷居を下げる。XのDM・InstagramのDM・メールの3本 (会社のXが無い担当者のためにメールを置く。Instagramは2026-09-04のゲート回答で残す)
- **CTA**: XのDM / InstagramのDM / メール。3本とも同じ幅

## 10. フッター (`#footer`)

- **誰に**: 全員 (再訪する人)
- **何のために**: 発信先とページ内リンクの一覧。読み終えた人が次に行く場所
- **なぜこの位置**: 末尾
- **何を載せるか**: リンク6つ (YouTube / X / GitHub / Instagram / Zenn / Substack)、このサイトの各セクション
- **CTA**: なし
