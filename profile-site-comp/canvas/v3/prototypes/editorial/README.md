# 白地・実績中心のローカル試作

Miyabiya Studioの9ページを、公開用の生成物から別フォルダへ書き出します。通常の公開ビルドでは、この試作を生成・配信しません。

Ryo Takemasaのサイトで参考にしたのは、白地、控えめな装飾、作品を先に見せる考え方です。左寄せの名前と1段のナビ、文章の2列配置、説明付きの2列の実績で、構成を独自にしています。参考サイトの画像・文章・コードは使用していません。

文字・背景・ボタン・入力欄・状態表示は、白・黒・グレーに統一しています。写真、サムネイル、作品画像、動画やスライドの埋め込みは元の色で表示します。画像ファイルは加工しません。

ボタンは全ページ共通で、主な操作を黒背景・白文字、補助の操作を白背景・黒文字にします。見積もりの戻る・選び直す・PDF保存・共有・閉じるも同じ配色です。ナビや本文内の参照は通常のリンクとして残します。

## 表示と再生成

- `build.py` は `output/editorial-concept/site/` に試作を生成します。既存の料金JSON・モジュールは維持し、画像は本人の既存素材を参照します。
- `monochrome.py` は、試作用にコピーするCSSとインラインSVGのUI色を無彩色にします。通常の画像URLと画像の色は維持します。
- `serve.py` はローカルの8777番ポートで試作を配信します。既存アセットは公開用の生成フォルダから読み取ります。別のoriginで同じパスを使うため、見積もりから問い合わせへの引き継ぎも確認できます。
- `canvas/v3/build_review.py` は、試作がある場合に既存レビューへ「新デザインの試作」を追加します。参考サイト一覧がある場合は、そのタブも維持します。
- 再生成の順序は、通常ビルド、`build.py`、`build_review.py`です。サーバーを起動したまま、同じレビュー用タブを再読み込みします。

## 試作で確認できる範囲

全ページの本文とナビ、見積もり、PDF保存、問い合わせ文の引き継ぎを確認できます。仕事の依頼と採用の判断に必要な内容を選び、ページごとに説明する役割を分けています。

| ページ | 残す情報 |
| --- | --- |
| トップ | 短い紹介、代表実績3件、依頼・採用の入口 |
| 実績 | AI導入・MCPの担当範囲と成果、制作物へのリンク |
| 経歴 | 職歴3件、主な技術、採用・業務委託の相談 |
| 依頼できること | 開発・AI導入・PRの対応範囲、登壇・編集の案内 |
| PR | 制作例1件、視聴者の特徴と規模、料金・相談 |
| 登壇 | 実績2件、スライドへのリンク、テーマ・形式 |
| お問い合わせ | 既存フォーム、返信目安、短い依頼の流れ |

最新動画の一覧、細かな工程別の作業時間、繰り返していたサービス説明やSNSの一覧は外しました。登壇スライドは閲覧したい方がリンクから開きます。メンバーシップはPRページ末尾の視聴者向け案内に残し、見積もりページの本文・選択・料金・旧URLの処理は維持します。

`content.py` が各ページの本文を生成します。`validate.py` で、内部リンク・画像、見積もりのDOMと料金データ、問い合わせフォームの互換性を確認できます。確認記録は `output/editorial-concept/selection/` に保存します。レビュー上部は試作・従来の構成・参考サイトに絞り、それ以前の画面は「過去の確認」から開けます。

問い合わせの実送信は止めています。問い合わせフォームだけを対象に送信イベントを抑止し、元のインライン処理の送信先もローカルへ置き換えています。旧URLのPDF保存用フォームは抑止しません。Analyticsも試作HTMLから除去します。

公開デザインへの採用は未確定です。確認記録と画面は `output/editorial-concept/` に保存します。
