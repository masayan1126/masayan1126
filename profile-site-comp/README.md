# Miyabiya Studio のサイト管理

[Miyabiya Studio](https://studio.msyn.me/)と[PR動画制作の見積もり](https://studio.msyn.me/pricing/)を管理します。

現在公開しているサイトは `canvas/v3/` から生成します。ルートの `build_site.py` と `canvas/build.py` は旧版用です。現在のサイト更新には使用しません。

2026年10月27日から、採用した文章中心のデザインを公開ビルドへ組み込みます。`build_public.py` が従来の本文・料金資産を `output/editorial-base/site/` へ生成し、`prototypes/editorial/publish.py` が公開用の7ページを `canvas/v3/site/` へ組み立てます。本文・共通ヘッダーは `prototypes/editorial/content.py`、余白と配色は `compact.css`、見積もりの見た目は `pricing-local.css`、文字サイズは `prototypes/typography/scales.mjs` が正本です。レビュー画面・未採用案・プレビュー用の送信防止は公開しません。

## 情報の優先順位・見た目・動き

サイト更新では[AGENTS.md](AGENTS.md)から[update-miyabiya-studio](.agents/skills/update-miyabiya-studio/SKILL.md)を読みます。情報の絞り込み、余白・近接によるまとまり、無彩色のUI、文字、アイコン、ホバー、アクセシビリティの方針はスキルを正本とします。採用済みの構成と生成元も、同スキルの参照資料へまとめています。

## 実績の数字を書くとき

計算で出した数字（削減時間・削減率など）の根拠は、元データと実績の記録へ残します。公開画面には、対象や比較条件など判断に必要な情報を簡潔に添えます。

- 例: 月230〜350時間 → `月平均30件 ×（従来8〜12時間 − 改善後20分）＝ 月230〜350時間`
- 数字を変えたら、根拠の式も同時に直します。トップ・実績カード・実績ページ本文・`test-fixtures/approved-works-*.html` の数字をそろえます

## トップへまとめた情報の整合

活動紹介はトップへ集約しています。新しい項目のためだけに詳細ページを作らず、[採用済みの構成](.agents/skills/update-miyabiya-studio/references/current-site.md)に従います。料金・実績・人数など、複数箇所に表示する情報は共通データから生成し、表記と条件をそろえます。

`validate_home.py`は、公開用の元データと生成に関する検査を担います。採用済みの7ページは、`prototypes/editorial/validate.py`でも本文・リンク・料金・フォームの互換性を確認します。旧いトップと詳細ページの対応表を、現在のページ追加の要件にはしません。

## 全ページの見た目を変更するとき

2026-10-25の指摘を受け、先頭画面と数値検査だけで完了にしない運用にします。旧ボタンの修飾クラスだけが残ると、文字の後ろだけに背景が付きます。近い色の面を親子に重ねると、情報の区切りも分かりません。

- CTAは `site_journeys.py` の共通部品を使います。旧本文のボタンも生成時に移行し、`validate_home.py` が不完全なクラスを検出します。専用の見積もり操作も同じ主・副の役割で確認します。
- 背景はカードの有無で自動的に決めず、内容の役割を持つ節へ指定します。本文・根拠・操作を余白と配置で分け、装飾の上線・左線を加えません。
- 採用済み7ページのうち変更の影響があるページを末尾まで見て、折りたたみ、見積もりの質問・完成・代替案・旧版・PDFダイアログなど該当する状態をPCとスマホで確認します。コントラスト・操作寸法・はみ出しに加え、実画面のまとまりも確認します。
- 参考にした一次資料、今回の適用、確認方法は [サイトの設計根拠](docs/site-design-practices.md) にまとめます。代表価格は `build_pricing_examples.mjs` が公開用の共通計算から生成し、手入力しません。
- 見積もりのフォーム引き継ぎは `quote-contact.mjs` を使います。同じブラウザタブ内の一時保存で受け渡し、受信後に消去します。料金をURLや入力本文から上書きしません。

## 動作確認

Python 3 と Node.js を使用します。初回は `npm ci` で依存パッケージをインストールしてください。このディレクトリで次のコマンドを実行します。

```sh
npm ci
npm run build
npm test
npm run preview
```

プレビューは `http://127.0.0.1:8769/` で確認できます。公開用の生成先は `canvas/v3/site/` です。

現在のトップは、白背景の短い自己紹介と活動一覧です。`home-3d/`にある映像・描画資産は旧いデザインのもので、通常の更新では使用しません。

全ページのレビューは `python3 canvas/v3/build_review.py` で生成します。`python3 canvas/v3/preview_review.py` でサーバーを起動し、`http://127.0.0.1:8776/review.html` で確認できます。更新後は同じタブを再読み込みしてください。

見積もりの「以前の比較3案」も、このレビュー内で切り替えて試せます。A案の「1問ずつ選ぶ」操作を共通にし、別の見積もりを①完成直後に並べる、②画面下の固定バーで案内する、③比較画面へ切り替える、の3案で確認できます。「完成画面から3案を比べる」で質問を省略して確認でき、完成後に1・2・3を切り替えても回答を保ちます。ダイアログ・質問・見積書・比較カードに短いアニメーションを加え、動きを減らす設定では停止します。生成元は `pricing-flows.html`・`pricing-flows.css`・`pricing-flows.mjs`、生成処理は `build_pricing_flows.mjs` です（いずれも `canvas/v3/` 内）。`pricing-flows-model.mjs` が、以前の固定料金にそろえた確認用データと、別パターンの見積もりを作ります。比較3案は旧料金版 `04da1a7ceffd` を使う操作の記録です。現在の制作オプションは「採用した見積もり」で確認します。単独ショートは税込10,000円です。ほかの未設定料金・条件は要相談のままです。公開用のデータは書き換えず、計算だけ共通の処理を使います。大きなダイアログで回答を変更でき、見積書の印刷・ブラウザのPDF保存と相談文の確認に対応します。比較用の選択内容が公開用の見積もりと混ざらないよう、この試作に公開用の共有URLは付けません。レビューの生成前に通常のサイトビルドを実行してください。3案は本人確認用で、公開ビルドには含まれません。

2026年10月25日に②の固定バー案を採用しました。公開ページは、大きなダイアログ内で1問ずつ回答し、最後に概算見積書を表示します。完成後は画面下の固定バーから、回答を引き継いだ残り6構成を比較できます。選んだ案の共有URL・PDF・問い合わせ文も共通の計算結果を使います。短いアニメーションを加え、動きを減らす設定では停止します。既知の作業は従来の上限額で固定し、本編・説明資料・サムネイル込みは税込53,000円です。単独ショート（60秒程度・1本）は税込10,000円で固定しました。修正・納品条件など、未設定の条件は要相談を維持します。X動画シェアは追加指定により1回税込1,500円です。過去の料金版を保持し、料金版を含まない作業選択だけの旧URLは `17268bfca1d6` へ復元します。

同じサービス・製品のPR依頼歴は「ある／ない」で回答します。「ある」は事前検証費用0円、「ない」は税込8,800円です。`researchPolicy: prior-pr-request` の料金版で適用し、`items` の事前検証の有無から回答を復元します。画面・PDF・問い合わせ文には同じ確認結果を載せます。旧料金版の任意チェックは保持し、現行版への切り替え時は依頼歴を確認する画面を開きます。

公開前の軽微修正は、本編・ショート・Xで希望回数を分けます。各2回まで料金内で、3回目以降は1回あたり本編5,500円・ショート3,300円・X1,000円（税込）です。料金と無料回数は `mediaRevisionRates`、回答は `revisionCounts` を正本とし、共有URLの `mainRevisions`・`shortRevisions`・`xRevisions` で復元します。選択していない媒体には加算しません。旧料金版の一括回数・未確定条件は維持します。

追加の希望の料金プレビューは、`pricing-model.mjs` の `extrasPresentation` で作ります。共通の計算結果から、各媒体の追加修正料と個別見積もりの項目を分けて表示します。未確定の料金を0円に置き換えたり、小計に含めたりしません。

追加の希望は1,000文字までの自由入力です。`notes` として共有URLに保存し、同じ入力を概算見積書・PDF・問い合わせ文に載せます。入力内容の料金は要相談とし、本編の軽微修正の加算とは分けます。過去のURLの相談項目は自由入力欄へ引き継ぎ、既存の料金・料金履歴は維持します。

`python3 canvas/v3/validate_home.py` は、全ページのリンクと見出し、元の本文と料金の維持を検査します。レビュー用HTMLは公開用の生成先に含まれません。

## OGP・検索・保存用アイコン

公開する付帯情報は `canvas/v3/site_metadata.py` を正本とし、`prototypes/editorial/build.py` が最終出力へ適用します。トップは「Miyabiya Studio | Masaya Nishigaki」、ほかのページは「ページ名 | Miyabiya Studio」。本文の内容に合う説明文・OGP・Xカード・構造化データを同じ設定から生成します。

`canvas/v3/build_og.py` は、採用C案のモノクロドット絵、曲線m、IBM Plex Sans JPを使い、通常OGP7枚・X用7枚と保存用アイコンを生成します。PillowとfontToolsを使うため、ブラウザや外部への画像送信は不要です。画像はいずれも1200×630pxです。通常の`og:image`は中央630px内に収め、正方形の切り抜きでも見切れない配置を保ちます。安全範囲はx=309〜891px、y=48〜582pxです。`twitter:image`には専用の横長画像を設定し、屋号とアバターを拡大して左右に広く配置します。横長用の安全範囲はx=128〜1072px、y=48〜582px、文字サイズは80・36・28pxです。画像の使い分けは各メタタグで指定し、画面幅や切り抜き形状による自動選択は行いません。

画像の文言・アバター・マーク・フォント・描画コードを変えたら生成を実行し、生成元と資産のハッシュを持つmanifestも更新します。通常ビルドはmanifestと入力の一致を検査し、再生成漏れを止めます。OGPの公開URLは内容のハッシュ付きとし、faviconのURLは固定します。検索・SNS側のキャッシュによる実際の表示変更は、公開HTMLの更新と区別して確認します。

旧い `site/og-profile.png`・`site/og-pricing.png` などは、過去URLの互換用です。現在のメタ情報からは参照しません。既存レビューの「OGP・メタ情報」で、変更前後・ページ別の検索とシェア表示・アイコンを確認できます。

「SNSでの表示」には公開7ページから取得したデータを使い、横長・正方形・小さな共有カードを表示します。取得日時と取得値も確認できます。公開情報を取り直す場合は `python3 canvas/v3/prototypes/metadata/fetch_public_preview.py`、続けて `python3 canvas/v3/prototypes/metadata/build.py` を実行します。通常のレビュー生成では保存済みの `public-preview.json` を使います。各SNSの実カードやキャッシュを取得する機能ではありません。

## 公開

Cloudflare の対象アカウントで認証してから実行します。

```sh
npm ci
npm run deploy
```

公開先は既存の Cloudflare Pages プロジェクト `miyabiya-studio` です。GitHub へのpushだけでは公開サイトを更新しません。

公開ビルドはフォーム送信と既存のGA4を有効にし、正規URLと7ページのサイトマップを生成します。加工したJS・CSSは内容から新しいファイル名を付け、古いキャッシュと混ざるのを防ぎます。`npm run build` は公開専用の検査まで行い、プレビュー送信先・noindex・欠けた資産・料金履歴の変更があれば停止します。

## 共有した見積もりを保つ

`canvas/v3/pricing-rates/` は、過去に共有した見積もりの料金表です。各ファイルを編集・削除せず、Gitへ保存してください。料金を変えてビルドすると、新しい料金表が追加されます。既存の共有URLは共有時の金額を保持します。

生成済みのサイト、作業用プレビュー、認証キャッシュはGitに含めません。非公開の原資料と監査記録はローカルに保存し、公開用の料金根拠と分けて管理します。

## 見積書のPDF出力

PDFには、画面で選択した作業・金額・税額と、入力した宛名を記載します。宛名は外部に送信せず、ブラウザ内でPDFを作成します。共有URLから開いた場合は、共有時の料金を使います。PDFの末尾にも、同じ選択内容を開くリンクを付けます。

日本語フォントとPDF用ライブラリは、ダウンロード操作時に読み込みます。フォントの出典とライセンスは `canvas/v3/pdf-assets/` に保存しています。


## 本編・ショート・X投稿の見積もり

2026年10月24日から、`mediaSchema: 1` の料金表で7構成を扱います。`pricing-model.mjs` の `quote` と `quotePresentation` を、画面・問い合わせ本文・PDFが共通で使います。本編の既存作業単価と税の扱いは維持します。

- `mediaRates` は新しい料金・条件の設定です。未設定は `null` とし、0円の確定料金と区別します。単独ショート、X製品PR投稿、動画のXシェア、切り抜き型と別撮影型の追加ショートを分けます。
- 本編と追加ショートは、検証・撮影を重ねて加算しません。既存の追加ショート・SNSシェアの料金は引き続き参照しますが、本数や未確定条件を確定済みとは表示しません。
- 新URLの `media` は `main`・`short`・`x` だけを受け付けます。追加修正と相談項目も復元します。媒体指定のない旧URLは、共有時の料金版による本編見積もりです。URLから料金を上書きする機能はありません。
- 個別契約の金額や本人確認用の仮条件は、Git対象外の `docs/pricing/private/media-reference.json` に保存します。公開データ・公開ビルド・料金履歴へ混ぜません。
- 非公開条件の検算は `PRICING_PRIVATE_FIXTURE` にそのファイルの絶対パスを指定して `npm test` を実行します。指定がない通常のテストでは、非公開条件の検算だけをスキップします。
- 本人確認用の比較資料は `node canvas/v3/build_pricing_review.mjs` で作り、既存の `build_review.py`・`preview_review.py` に束ねます。この生成処理は公開ビルドから呼びません。公開用の操作画面と、本人向けの参考額を同じレビュータブ内で確認できます。

## 制作オプションの選択

2026年10月25日の追加指定により、`mediaSchema: 2` から本編の事前検証を任意にしました。初期状態では事前検証・企画と台本・サムネイルを選択し、事前検証を外すと税込8,800円を減額します。追加回答により、公開30日後のレポートは新しい選択肢・明細・取引条件から削除しました。YouTubeへの公開作業は税込2,200円を維持します。

本編とショートを選んだ場合は、切り抜き型（追加0円）と、別撮影・大幅な内容変更（追加10,000円）を別の質問で選びます。Xでの動画シェアは、媒体の選択画面で独立して選択し、1回税込1,500円で計算します。X単独の製品PR投稿は別の扱いとして要相談を維持します。旧セット料金を新しい計算へ加算しません。単独ショートは1本税込10,000円です。

新URLは `shortMode` も復元します。`report` などの任意の料金・条件指定は計算に使いません。料金と選択規則は共有時の料金版で処理し、過去のURLの検証必須・レポート込み・セット料金を変更しません。比較する別案にも、事前検証などの選択・ショートの制作方法を引き継ぎます。未設定の追加料金は選択時のみ要相談とし、金額が分かる項目の小計に含めません。
