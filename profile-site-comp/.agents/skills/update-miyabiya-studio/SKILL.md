# Miyabiya Studioを更新する

このセッションで本人が決めたサイトの方針を、更新時の判断基準にする。最新の本人の指示を優先し、過去の比較案や一度限りの変更を恒久ルールにしない。

基本は「シンプル、要素や内容、セクションのまとまり、ゴチャつきがない」。情報を増やす前に、必要な内容を選び、関係が伝わる配置に整える。

理由：装飾・説明・導線を追加し続けると、活動や実績を読み取りにくくなる。依頼を検討する人が、必要な情報と次の操作をすぐ見つけられる状態を保つ。

## 情報を選び、まとめる

- 活動の理解、実績の確認、仕事の依頼に役立つ情報を優先する。重複、長い補足、抽象的な誘い文句を減らす。
- 全体も各セクションも、概要・結論から内訳・具体例へ進める。自己紹介に書いた活動の順序と、本文の並びを合わせる。
- 同じ話題の見出し・本文・実績・リンクを近づけ、別の話題との間隔を広くする。関連の強さを余白の差で表す。
- 左端、画像の大きさ、ラベルの位置、一覧の列幅をそろえる。文字を減らすだけで整理したことにしない。
- ページ冒頭のタイトル・説明から本文までを空けすぎない。画面幅に応じて間隔を調整する。
- 活動の概要はトップへまとめる。項目を追加するたびに詳細ページやカードを増やさない。現在の構成は[採用済みの構成](references/current-site.md)を確認する。

## 見た目をそろえる

- 白背景を基本とし、UIの文字・背景・部品は黒と無彩色のグレーにする。写真、動画、OGP画像、製品・SNSの実アイコンは元の色を保つ。
- 薄い青の背景に青文字・青い部品を重ねる表現を戻さない。各ページの冒頭も白背景にする。
- 文字と情報を主役にし、画像ギャラリー中心の構成やカードの乱用を避ける。カード上辺・左辺の装飾線は使わない。
- 要素の区切りは余白・近接・整列で表す。装飾目的の囲みやボーダー下線を足さない。入力欄、選択状態、フォーカスなど操作に必要な輪郭は残す。
- 主ボタンは黒背景・白文字、補助ボタンは白背景・黒文字。本文リンクにも下線を付けず、文言・配置・適切なアイコンで役割を伝える。
- 癖のないゴシック体と少数の文字サイズを使う。既存の3段階程度の尺度を優先し、変更ごとにサイズを増やさない。採用済みの小さな補足サイズは機械的に戻さない。
- 同じ役割のアイコンは線幅・大きさをそろえる。意味の分かるものを選び、装飾だけのアイコンを増やさない。SNSや拡張機能には実際のアイコンを使う。
- トップ、お問い合わせ、見積もりページ、見積もりダイアログで、配色・文字・余白・操作部品をそろえる。

## 文言を短く、具体的にする

- [write-readable-content-for-web](/Users/masayan/.claude/skills/write-readable-content-for-web/SKILL.md)を文章の正本として使う。
- 「一緒に取り組めることがあれば」のような曖昧な呼びかけを避け、活動・実績・操作を具体的に書く。
- 活動や実績の箇条書きは、意味が保てる範囲で体言止めなどを使い、短くする。全ての説明文を機械的に体言止めにしない。
- 不要な補足を省き、判断に必要な対象・条件は残す。数値の根拠は元データや記録に保持し、画面へ長い説明を追加しない。
- 登録者・メンバー・利用者数は実際に確認した数値と確認日を使う。古い数値へ「現在」の日付だけを付け直さない。
- 内部の制作手順や検証報告をサイト本文に混ぜない。

## 動きとアクセシビリティを両立する

- 操作できる要素のホバーは、控えめに浮く動きへ統一する。背景・文字・枠の色、影、下線、透明度、フィルターをホバーで変えない。
- 親子の部品を二重に動かさない。無効な操作や、入力中の欄は動かさない。静的な本文へ操作を連想させる動きを付けない。
- 背景の常時アニメーションや装飾的な動きを増やさない。「背景の動きを止める」という独立した操作を戻さず、OSの動きを減らす設定へ対応する。
- ホバーの色変化を除く際も、選択状態、入力エラー、キーボードのフォーカス枠は維持する。
- 背景と文字のコントラスト、読み上げ名、キーボード操作、押せる範囲を確認する。装飾アイコンは読み上げから外し、リンクやボタンには操作が分かる名前を残す。
- 固定ヘッダーやダイアログで、本文・リンク・フォーカスを隠さない。スマホで文字、画像、列、長いラベルが欠けないようにする。

## 更新を進める

1. `TODO.md`と変更対象のソースを読み、依頼範囲と採用済みの状態を確認する。生成済みHTMLだけを修正しない。[生成元と検証](references/maintenance.md)から該当するファイルを選ぶ。
2. 必要な情報を選び、配置・文言・余白を整えてから装飾を検討する。参考サイトは、情報のまとめ方や密度の参考にし、外観・素材・文章をそのまま複製しない。
3. 本人の判断が必要な案は既存のレビューHTMLへまとめる。同じ趣旨の別ファイルやブラウザタブを増やさない。指定された案数を用意し、毎回3案・5案の選択をやり直さない。
4. 変更に関係するビルド・検査を行い、PCとスマホで確認する。共通部品の変更では、影響するページと通常・ホバー・フォーカス・選択状態まで確認する。
5. 既存の公開指示と作業範囲に従って反映する。公開した場合は公開URLを再読み込みし、実際の表示と操作を確認してから完了とする。ローカル、マージ済み、公開済みを区別する。

このスキルの作成・保守だけの依頼では、サイトの表示や料金を変更したり、サイトを再デプロイしたりしない。
